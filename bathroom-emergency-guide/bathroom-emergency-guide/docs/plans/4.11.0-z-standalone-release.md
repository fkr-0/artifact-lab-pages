# Bathroom Emergency Guide 4.11.0 — Z standalone release

## Goal

Release **Z — Outage and Continuity** as a source-complete standalone family
without duplicating canonical prose or weakening the existing master guide.

## Readiness decision

Z is the next bounded extraction because it already owns seven reader-facing
visuals across priority, water, household systems, communication, and role
assignment. Its only numerical release gap at 4.10.0 is a fourth local source.
A remains master-only because one visual is not an equivalent standalone visual
language, even though its source count is already sufficient.

## Source hardening

- Add one local operational footnote beside the initial warning-verification
  instruction.
- Use current BBK pages for the Warn-App NINA and Cell Broadcast.
- Keep the claim narrow: NINA provides fuller official warning information;
  Cell Broadcast sends short direct warnings to compatible devices; use the
  warning mix and follow the issuing authority.
- Do not turn device requirements, availability, or warning receipt into a
  guarantee.

## Canonical extraction

- Build Z from `src/chapters/06-zombie-guide.md`.
- Add only the generated standalone cover, one page-zero emergency gate, graph
  orientation, handoff page, and generated local Sources and limits.
- Preserve the canonical chapter order, formulas, tables, text fallbacks, and
  all seven owned visuals.
- Do not create a parallel Z prose source.

## Release gate

Every A4, A4/2, and large-print colour/monochrome edition must retain:

- at least four local sources;
- all seven owned reader visuals;
- warning verification, household continuity, water planning, essential-
  treatment continuity, communication scaling, first-meeting roles,
  evacuation, and preparedness sections;
- exactly one emergency gate;
- generated local Sources and limits;
- tagged-PDF, geometry, page-count, semantic-text, colour/monochrome,
  accessibility, and overflow parity.

## Matrix and publication boundary

- Expand the released set from O/B/C/D/H/P/T/R to O/B/C/D/H/Z/P/T/R.
- Expand standalone PDFs from 48 to 54.
- Keep A master-only.
- Update graph hub, landing page, download catalogue, release metadata,
  validators, changelog, README, roadmap, and in-guide version history.
- Build and test at an exact source revision before creating an annotated local
  `v4.11.0` tag.
- Do not push, publish, deploy, or run the prepared Pages deployment workflow.

## Evidence boundary

Passing the build proves canonical extraction, source attachment, rendering,
tagging, geometry, accessibility, and package integrity. It does not prove that
a real household received a warning, retained power or water, completed an
evacuation, or successfully operated the continuity plan during an incident.
