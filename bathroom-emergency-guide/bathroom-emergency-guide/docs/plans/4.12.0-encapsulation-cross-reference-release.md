# Bathroom Emergency Guide 4.12.0 — encapsulation and cross-reference release

## Goal

Make every standalone route feel like a complete field object rather than an
excerpt, while preserving one canonical source tree. Extend the route identity
system into figures, forms, professional handoffs, and Reference without making
colour the only carrier of meaning.

## Writing pass

- Rewrite support selection around the concrete change a service can make.
- Distinguish reaching a service from completing a usable handoff.
- Replace duplicate contact and fillable-field tables with canonical Blue Book
  forms and stable references.
- Clarify how eight legacy situation doors map into ten maintained route
  identities.
- Keep emergency action ahead of appendix or index reading.

## Standalone encapsulation

Every released standalone family must include:

- an explicit inside-scope statement;
- a deliberate boundary;
- canonical chapter and legacy aliases;
- an exit rule;
- a local figure, form, support, and route map;
- complete local sources and limits;
- one page-zero emergency gate;
- the existing graph handoff and revision provenance.

The generated standalone manifest records those fields so encapsulation is a
validated contract, not cover copy.

## Route identity grammar

Each route retains a unique:

- code;
- title;
- colour;
- print-safe geometric pattern;
- glyph name.

Code and title are primary. Colour accelerates scanning. Pattern and written
glyph name preserve the identity in monochrome, speech, low-colour printing,
and accessible handoffs.

## Figure cross-references

Every canonical figure occurrence receives a generated card containing:

- stable figure address;
- owning route identity;
- pattern and glyph name;
- reader question;
- paired Blue Book forms.

Reference receives a generated illustration index joining the same figure to
its route and forms. The nearby prose remains the complete non-image route.

## Template and support cross-references

Every canonical Blue Book form receives a generated route band containing:

- stable form address;
- privacy class;
- operational route chips;
- related figure references;
- related professional-support references.

Professional Support receives a generated handoff map joining services, forms,
figures, and route identities. Reference indexes those relationships without
maintaining a second writable-form system.

## Stable-reference rule

Wording changes must not retire a public address when the resource still
exists. Planned heading rewrites therefore retain their prior resource keys.
Only a genuinely removed resource may become retired.

## Release gate

- Regenerate all inventories and stable-reference fragments.
- Preserve the single pre-existing retired historical key and no others.
- Build all six master editions and all 54 standalone PDF editions.
- Verify P, T, and R encapsulation specifically, including all eighteen form
  bands in T.
- Pass tagged-PDF, page-count, semantic-text, colour/mono, geometry, density,
  accessibility, overflow, and browser checks.
- Record exact-revision evidence before creating an annotated local tag.
- Do not push, publish, deploy, or run the prepared Pages deployment workflow.

## Evidence boundary

The build can prove source ownership, generated relationships, rendering,
accessibility, and package integrity. It cannot prove that a local service
answered, that a form was completed accurately, that a route worked under real
stress, or that the colour/pattern system has passed external usability testing.
