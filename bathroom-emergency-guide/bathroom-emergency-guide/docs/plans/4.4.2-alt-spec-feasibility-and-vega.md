# Bathroom Emergency Guide 4.4.2 — Alternate-Spec Feasibility and Vega Start

Status: implementation candidate
Base: `v4.4.1` at `2f34fd149b5791400ca6797cb648c2d545f30314`
Alternate proposal: untracked `src-alt/expansion-design.md`
Prepared: 22 July 2026

## Purpose

The alternate specification contains useful product architecture, but it mixes
four different things: navigation, visual identity, build topology, and proposed
new subject matter. Those layers do not have equal evidential risk. Version
4.4.2 adopts the low-risk structural ideas first and keeps content expansion
behind the existing source and route gates.

## Decision matrix

| Alternate proposal | Decision | 4.4.2 adaptation | Reason |
|---|---|---|---|
| Three-page visual hub | prototype | manifest and milestone contract first; hub rendering begins in 4.5 M2 | useful orientation, but must retain emergency deep links and accessible text |
| Ten equally prominent books | modify | nine-node core graph plus gated satellites | avoids ten loud entry doors and preserves current routing codes |
| Per-subguide colour | accept with constraint | colour + code + pattern + glyph | colour alone fails monochrome and colour-vision requirements |
| Pattern tiles | accept | stable tokens after A4/A4/2 print tests | useful redundant identity if stroke and repeat sizes are controlled |
| Mascot per guide | optional | never a release gate | decorative assets must not block navigation or evidence work |
| Separate handwritten source files | reject | generated filtered Sources and limits from one canonical registry | duplicated bibliographies drift and create conflicting ownership |
| Immediate physical source-tree reorganisation | defer | `src/data/subguides.json` maps existing canonical chapters first | moving prose before parity tests creates large, hard-to-review diffs |
| Per-subguide HTML/PDF/DOCX/LaTeX from day one | narrow | pilot B and H in HTML/PDF color+mono, then A4/2 | prevents an early 80–100-output validation explosion |
| Red-flag gate at every subguide top | modify | once in master; once on page zero only for standalone output | repetition in the master weakens hierarchy and wastes pages |
| Matplotlib for every diagram | modify | Vega-Lite for quantitative charts, Graphviz/SVG for topology, matplotlib for custom scientific explanations, semantic HTML for forms | tool follows question rather than visual fashion |
| One generator per visual style | modify | catalog-driven rendering families with shared tokens | avoids script proliferation and inconsistent provenance |
| New Body, Social, and Disaster books | defer behind graduation gate | remain satellite candidates or inserts | several proposed claims need primary-source review and route ownership |
| Warm direct voice | accept | humor stays away from red flags and uncertainty remains explicit | compatible with current editorial contract |
| No CDN and reproducible build | accept | local npm dependencies and deterministic SVG/PNG output | required for print and offline builds |
| “No open questions” | reject | milestone review records unresolved grouping, pattern, page-budget, and source-ownership choices | architecture still needs prototypes and measured trade-offs |

## Material explicitly not imported

The feasibility review does not authorize generic fever cut-offs, mole rules as
diagnosis, lightning 30/30 guidance, Beaufort action thresholds, improvised
sanitation distances, scavenging advice, or compressed legal and developmental
decision trees. Each would require its own source, denominator, locale, limit,
and route review.

## Implemented in 4.4.2

1. `src/data/subguides.json` defines the nine prototype graph nodes while the
   current chapter files remain canonical.
2. `bin/validate_subguides.py` validates identity, graph edges, chapter
   ownership, and master/standalone emergency-gate policy.
3. `src/data/visualization_catalog.json` defines eight initial Vega-Lite figures.
4. `src/visualizations/derive_data.py` derives reviewed chart tables from the
   evidence and continuity registries.
5. `bin/build_visualizations.mjs` compiles Vega-Lite offline and emits SVG plus
   print-resolution PNG fallbacks.
6. `bin/validate_visualizations.py` checks provenance, data/spec/output parity,
   accessibility text, monochrome redundancy, and reader references.

- SVG and PNG outputs exist and match catalog entries;
- every chart has question, takeaway, source class, denominator/scope, limit,

- all six document editions remain unclipped and text-equivalent;
